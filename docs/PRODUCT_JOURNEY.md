# CodeVivo Product Journey

## Purpose

This document defines the global CodeVivo Product Journey lifecycle used by Currently Building cards.

The Product Journey reflects product maturity, not amount of work done.

## Core Principle

The Product Journey reflects the maturity of the product, not the amount of effort spent.

Every in-progress project must use the same global lifecycle:

1. Idea
2. Research
3. Product Architecture
4. Core Features
5. MVP
6. Beta
7. Production

## Stage Criteria

### 1. Idea

**Meaning**

The project exists as a concept.

**Move to next stage when**

The problem is clear enough to justify research.

### 2. Research

**Meaning**

User needs, competitors, constraints and MVP direction are being explored.

**Move to next stage when**

The MVP direction is clear and the product has a defined scope.

### 3. Product Architecture

**Meaning**

Core architecture, UX flows, domain model, design principles, data model and technical foundations are being shaped.

**Move to next stage when**

The foundation is stable enough to build core features without constantly rethinking the product.

### 4. Core Features

**Meaning**

The essential user workflows are being implemented.

**Move to next stage when**

The main user workflow works end-to-end.

### 5. MVP

**Meaning**

A usable version exists.

**Move to next stage when**

A real user can complete the primary task, even if the product is still rough.

### 6. Beta

**Meaning**

The product is being tested with real users.

**Move to next stage when**

Feedback has been collected, major issues have been addressed, and the product is stable enough for public use.

### 7. Production

**Meaning**

The product is live, maintained, and usable by its intended audience.

## Rules

- Do not move a project forward because time was spent on it.
- Do not move a project forward because the UI looks better.
- Move a project forward only when the product itself has matured.
- A landing page alone does not move a project beyond Research or Product Architecture.
- Polishing does not equal progress.
- Real user workflows matter more than visual completeness.
- Every project must use the same global lifecycle.

## Current Examples

### Nine2Fire

**Current stage**

Product Architecture or Core Features depending on latest implementation maturity.

**Reason**

Editorial system, CMS workflow, content pipeline and tools are being shaped, but full product validation is still ongoing.

### deckLog

**Current stage**

Product Architecture.

**Reason**

Domain model, Fleet Explorer, localization, design principles and technical foundations exist, but core operational workflows are still being built.

## Interpretation Notes

Use the Product Journey to describe what the product can objectively do and how mature its real workflow is.

Do not interpret the bar as a measure of time invested, number of tasks completed, or visual polish.
